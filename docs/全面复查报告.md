## 修复的问题

| 问题 | 修复后的行为 | 验证方式 |
| --- | --- | --- |
| 同一天、相同标题的导出覆盖旧包 | 每次创建独立目录；写入失败清理本次未完成文件 | 连续导出不同正文，并模拟磁盘写入失败，旧包内容不变 |
| 同一模板的封面历史共用一个文件 | 每次渲染保存独立 PNG，历史文件与摘要保持一致 | 连续渲染同一模板，读取旧图并核对 SHA-256 |
| 刷新候选图重置未保存的封面设置 | 保留文案、模板、焦点与尺寸，仅在新渲染版本出现时恢复已保存值 | 前端回归及真实浏览器操作 |
| 旧异步请求覆盖新页面或新封面状态 | 过期响应被丢弃，文章切换后旧操作不会打开旧文章 | 人为延迟响应并切换文章、交错刷新 |
| 仅有 CORS，未阻止外部网页的简单 POST | 校验 Host、Origin 和浏览器跨站标记；外部网页请求在进入接口前被拒绝 | 验证外部来源未触发模拟付费操作，本机、IPv6 Host、局域网、开发预检仍可访问 |
| 损坏的图像配置导致封面页和设置不可用 | 暂停生图并提供可编辑的修复表单，本地封面功能仍可使用 | 分别模拟数据库和环境变量中的无效配置，再通过设置修复 |
| 密钥已更新但配置事务失败 | 地址与密钥摘要不匹配时阻止生图，重新填写后恢复 | 分别模拟旧版配置、已有绑定配置的数据库提交失败，以及凭据存储失败 |
| 发布扫描与复制读取了两次源码 | 复制扫描时的原始字节，ZIP 使用排他创建 | 扫描后修改源码，发布文件仍与扫描摘要一致 |

移除了 `publishing.py` 中重复的旧封面实现，统一使用封面工作台；迁移测试显式关闭 SQLite 连接，消除测试资源泄漏。

## 发布与验证边界

最新发布文件为 `release/chaoshi-yuji-reviewed-20260912.zip`，同名目录便于逐文件审阅。内含 `RELEASE_MANIFEST.json`，记录源码和文档的路径、大小及摘要；整个 ZIP 的摘要另存为同目录下的 `.zip.sha256` 文件。历史发布包分开保留。

发布包不含 `.git`、个人数据库、`.env`、密钥、上传图片、日志、虚拟环境、依赖目录或临时测试目录。示例截图只含虚构演示内容和明确标识的本地模拟图片。自动扫描不能替代所有者对自定义规则和截图的人工审阅。

真实图像服务的连通性、模型权限、计费和画面效果尚未验证；本轮未调用付费模型。Docker、Windows 原生 OCR 实际识别、计划任务安装和远端 GitHub Actions 也不列为实测通过项。局域网模式没有账号认证，仅用于可信网络；Host/Origin 校验不能替代网络访问控制。

后续修改可按“复现问题 → 修复 → 对应回归 → 完整检查 → 更新发布包”的流程继续验证。本报告只描述本轮已完成的工作。
